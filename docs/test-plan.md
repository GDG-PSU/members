Run `pnpm verify` to attempt available release checks. It reports missing prerequisites and unimplemented release gates as failures rather than treating them as passes. Use a disposable local/staging database; `db:verify` commits one concurrency fixture and one erasure fixture, then removes both through `erase_member`. Browser tests require a running app, Supabase keys, `E2E_BASE_URL`, and the same `CARD_WRITE_ENCRYPTION_KEY` as the app; the device spec sends `x-forwarded-proto: https` because device traffic must arrive over TLS in production. `pio` requires PlatformIO and the ignored firmware configuration.

- Shared firmware/server HMAC vector executed on the firmware target, device clock/network recovery, offline persistence, and two physical lanes.
- WCAG/axe audit and visual review at all requested breakpoints.
- Comprehensive secret scan, backup/restore rehearsal, and production configuration, DNS, Vercel or email delivery. The hosted project's Auth URL/redirect settings and the GitHub branching app still need an operator check in the dashboard.
- Rotate the Supabase secret key and database password that were shared in plain text; use the dashboard to roll them, then update Vercel and local `.env.local`.
- Physical ESP32, PN532, NFC tags, actual PSU network authorization and TLS trust.

`pnpm verify` must remain nonzero until the missing release gates are implemented and pass. Static NFC tags can be cloned and never authorize points or attendance without staff confirmation.
